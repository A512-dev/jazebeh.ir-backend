# Smart targeting flow: tag discovery and selection

`business_flow/smart_targeting_flow.go` provides customer-facing tag discovery and complete selection replacement. It does not calculate exact audience capacity or choose concrete audience members: see [capacity](smart-targeting-capacity-flow.md), [sampling](smart-targeting-sampling-flow.md), and [execution calculation](smart-targeting-execution-calculation-flow.md).

`SmartTargetingFlow` defines `ListTags`, `ListBundleTags`, `GetSelection`, `ReplaceSelection` and `AutoSelect`. `SmartTargetingFlowImpl` depends on campaign, bundle, selected-tag and evaluation-read repositories and a database. `NewSmartTargetingFlow` wires them. `ownedCampaign` validates customer ID and campaign UUID, loads the campaign, enforces ownership and requires a bundle. `evaluationAvailable` means at least one current score row exists, not merely that an evaluation was once attempted.

## Tag listing

`smartTargetingTagListOffset` validates request, page, page size (1–100) and nonnegative capacity; `smartTargetingPageOffset` guards integer overflow. `normalizeSmartTargetingQuery` trims search, limits it to 200 runes, validates direction and sort and selects defaults. Execution campaigns default to execution-specific ordering using test CTR then persona fit; other evaluated bundles default to persona fit descending; unevaluated bundles default to database order. Persona-fit ordering requires current scores, and internal default sorts cannot be requested as arbitrary public sort values.

`listAvailableTags` applies these rules and delegates filtering, count and paging to the selection repository. `smartTargetingTagListSource` carries bundle/campaign context and the evaluation and execution flags. `smartTargetingTagItem` maps the projection to a DTO; unavailable metric pointers remain distinct from measured zero.

`ListTags` checks campaign ownership and adds the complete persisted selected-tag ID list and summary to the paginated available rows. This lets a client page through candidates without losing selections on other pages. `ListBundleTags` checks bundle ownership and offers discovery before a campaign exists; its selection and summary are empty.

## Selection lifecycle

`GetSelection` loads selected rows and summary for the owned campaign; `selectionResponse` maps them. `normalizeSelectedTagIDs` validates the submitted IDs and enforces the 10,000-selection ceiling. `replace` coordinates a complete selection replacement in a transaction, rather than incrementally merging a page of changes; `ReplaceSelection` exposes it to callers. `AutoSelect` obtains matching available IDs and uses the same replacement path. The repository checks editability and availability, preserves requested order, snapshots tag details and performance, and invalidates an obsolete test preview when the selection changes. See [selected-tag repository](campaign-selected-tag-repository.md).

Selection is a configuration snapshot, not an audience reservation. A selected tag's raw capacity may overlap another tag's; use the capacity calculation for a deduplicated, eligibility-aware result.
