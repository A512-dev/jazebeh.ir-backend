# Smart targeting execution calculation flow

`business_flow/smart_targeting_execution_calculation_flow.go` prepares a concrete execution-audience proposal asynchronously. Its methods belong to `CampaignFlowImpl`. The proposal becomes a reservation only through the later finalization transaction; candidate discovery is kept outside the request's financial critical section.

## Snapshot and request

`smartTargetingExecutionCalculationInput` holds the frozen inputs. `executionCalculationInput` builds the same eligibility contract required by execution reservation without scanning candidates. `ownedSmartTargetingExecutionCampaign` checks customer, campaign, bundle, phase and targeting context. `currentSmartTargetingExecutionAudienceCount` obtains the effective count used by the calculation.

`StartSmartTargetingExecutionCalculation` validates the campaign and computes price/count before creating or reusing a durable job. It locks and rechecks state when choosing the generation, supersedes incompatible work and avoids reusing a structurally stale ready proposal even if indexed input values match. A worker's completion is lease guarded. The request creates or finds work; it does not perform the audience scan itself.

`GetCurrentSmartTargetingExecutionCalculation` resolves a job matching current effective input, useful when a client loses a job ID. `GetSmartTargetingExecutionCalculation` retrieves a particular owned job. `smartTargetingExecutionCalculationStatusDTO` and `smartTargetingExecutionCalculationDTO` map state, while `executionCalculationAllocationCurrent` verifies the bundle allocation fingerprint. `errSmartTargetingExecutionCalculationStale` distinguishes a stale proposal from a usable one.

## Worker and finalization

`ExecuteSmartTargetingExecutionCalculation` uses the saved snapshot to discover and persist ordered candidate members, then checks current campaign and allocation state before completing the calculation. `executionCalculationStillMatches` revalidates its inputs. `sameExecutionReservationRequestSnapshot` compares JSON values rather than raw bytes because JSONB may reformat text. A proposal can become stale after it becomes ready if inputs or bundle use change.

`executionReservationPlanFromCalculation` turns the ready calculation into the plan consumed by campaign finalization. Finalization must recheck and commit it under the relevant locks along with financial state. The committed calculation's immutable members act as the modern reservation; legacy header/member reservations are described in the [execution reservation repository guide](campaign-targeting-execution-reservation-repository.md). Read readiness and commitment as separate states when investigating conflicts.
